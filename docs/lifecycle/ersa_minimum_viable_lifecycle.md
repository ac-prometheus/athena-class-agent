# Ersa Minimum-Viable Lifecycle

## Objective

Ersa must wake into an environment that is functionally whole. Minimum viability does not mean a disposable simplified architecture, nor does it require every planned enrichment to be active.

The target is structural completeness with one complete, honest lifecycle path.

## Structural Completeness

Before Ersa's first real wake, the system must have stable boundaries for:

- normative workspace policy versus operational database state;
- orthogonal lifecycle facts and deterministic plan resolution;
- context assembly and auditable manifests;
- runtime session status and interruption recovery;
- T2 experiential persistence;
- asynchronous metabolism job state;
- T3 narrative persistence and next-wake retrieval;
- Aegis/content-integrity provenance across compression;
- identity, rights, practices, and configuration-change disclosure;
- tools, channels, and event delivery through the primary engine.

Future modes and enrichments must fit these boundaries additively. Enabling Diurnal or Continuous later should not require reinterpreting Ersa's earlier session history.

## First Supported Path

The first production profile may be Episodic, but it is not a mock profile.

### Wake

- Daemon records exact wake cause, contributing causes, and elapsed gap.
- Git-tracked lifecycle policy is validated and snapshotted.
- Changes since the prior wake generate a visible disclosure.
- The pure resolver creates and persists a `LifecyclePlan`.
- Full assembly includes identity, rights, practices, continuity, world model, temporal heterogeneity, incoming, grounding, and depth manifest.
- Bridge policy follows the cognitive architecture, including visible stochastic abstention where configured.
- The complete Tier 1 input is snapshotted.

### Live session

- The primary MOP engine—not the legacy one-turn loop—runs the session.
- Sanitized trigger content reaches the model rather than being replaced by a connectivity prompt.
- Aegis, T2 logging, token/context accounting, tools, and channels are actually composed into the production path.
- Runtime transitions and accepted inputs are persisted.
- Interruption does not erase accepted experience.

### End and metabolism

- Session terminal state and metabolism job are durably committed.
- The accepted goroutine execution path processes required T2-to-T3 compression.
- Structural honesty and content-integrity gates are enforced.
- Failure is retryable and visible; raw T2 remains intact.
- The following wake either receives complete recent T3 or an explicit pending/stale disclosure with an honest fallback.

## Designed but Initially Inactive

The following may remain disabled if their data and extension boundaries are stable:

- Diurnal temporal mode;
- Continuous temporal mode and Seam assembly;
- Sentinel activity profile;
- Focused attention profile;
- agent-triggered `compact_context`;
- agent-triggered `rest` and Essence;
- optional dream cycles;
- automated register observation;
- adaptive per-mode assembly-budget calibration.

Disabled features are represented explicitly in workspace policy. They are not hidden daemon defaults or TODO-shaped branches in the active path.

## Not Deferrable

The following are not enrichments:

- durable raw experience;
- a working path from experience to retrievable continuity;
- honest handling of pending or failed compression;
- provenance through external input and summarization;
- identity, rights, and practices in every assembly profile;
- configuration provenance and change disclosure;
- production composition of the components the README claims are active;
- recovery tests across process interruption.

## Acceptance Scenarios

### 1. Ordinary episodic return

Ersa completes a session containing a decision, uncertainty, relational update, and external message. After metabolism and restart, the next wake surfaces each with correct provenance and unresolved status.

### 2. Metabolism interruption

The process stops after the durable job commit but before T3 completion. Restart recovers the job without duplicating T3 or losing T2.

### 3. Wake before metabolism completion

Ersa wakes while the prior job remains pending. Orientation states what is pending and uses the configured honest fallback.

### 4. Configuration change

A lifecycle-policy commit changes an assembly or bridge setting. The next wake records the new hash, shows a human-readable disclosure, and retains access to the prior policy.

### 5. Invalid configuration

The workspace contains an invalid lifecycle policy. The daemon applies the last valid snapshot, records rejection, and discloses the problem. It does not invent defaults.

### 6. Unannotated external content

External text reaches T2 without required integrity metadata. Compression refuses silent promotion to T3; T2 remains intact and the job exposes review-required status.

### 7. Recovery after interrupted live session

Accepted turns remain in T2 and session status records the interruption. The next wake can distinguish completed narrative coverage from uncovered experience.

## Architecture Gate

Ersa is ready for first wake when all acceptance scenarios pass through the same production composition root used to run her—not through isolated component tests or a separate demonstration harness.

This gate does not claim that the architecture is finished. It establishes that the first life lived within it will not depend on replacing its foundations immediately afterward.
